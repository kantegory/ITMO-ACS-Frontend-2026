## API и авторизация

`src/api.js` выполняет запросы через fetch, передаёт Bearer-токен, обрабатывает HTTP-ошибки, отсутствие соединения и таймаут. Фильтрация выполняется сервером. В localStorage больше нет базы рецептов или пользователей; сеанс входа хранится в sessionStorage.

Моковое API построено на `json-server` 0.17.4. `server/app.js` использует JSON-хранилище router.db и собственные маршруты с проверкой данных и прав. Пароли хешируются bcrypt. JWT действует 24 часа; подпись, срок, издатель и аудитория проверяются при запросе. Пользователь каждой новой записи определяется по токену. Удалять можно только собственные комментарии, лайки, сохранения и подписки.

| Маршрут | Назначение |
|---|---|
| `POST /auth/register`, `POST /auth/login` | Регистрация и вход |
| `GET /me`, `PATCH /me` | Собственный профиль |
| `GET /authors`, `GET /authors/:id` | Публичные данные кулинаров |
| `GET /recipes` | Каталог; параметры search, type, difficulty, ingredient, sort, authorId |
| `GET /recipes/:id`, `POST /recipes` | Рецепт и публикация |
| `GET/POST /comments`, `DELETE /comments/:id` | Комментарии |
| `GET/POST /likes`, `DELETE /likes/:id` | Отметки нравится |
| `GET/POST /saved`, `DELETE /saved/:id` | Личные сохранения |
| `GET/POST /follows`, `DELETE /follows/:id` | Личные подписки |

Все маршруты таблицы имеют префикс `/api`. База создаётся при первом запуске из `src/seed.json` в `.runtime/db.json`. Данные и случайный ключ JWT сохраняются между запусками. `.runtime` исключена из Git. Вместо генерируемого ключа можно задать `JWT_SECRET` длиной не менее 32 байт. Список пользователей, хеши и файл базы через HTTP не выдаются.

## Проверка

```sh
npm test
npm run build
npm audit
```

Тесты используют отдельные базы в `.runtime/api-test-*`. Проверяются авторизация, неверные и просроченные токены, нормализация email, ограничение пароля в 72 байта, скрытие приватных полей, права на удаление, изоляция сохранений, защита полей профиля, валидация публикаций и сохранение данных при повторном запуске сервера. Все проверки проходят; npm audit - 0 уязвимостей.

В браузере проверены вход через API, серверная фильтрация, лайк и его снятие, добавление комментария, его сохранение после перезагрузки и удаление, а также страница отсутствующего рецепта (HTTP 404). Остальной интерфейс и структура страниц сохранены из ЛР1.
