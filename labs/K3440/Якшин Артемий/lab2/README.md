# ЛР2. «Поварёшка» — работа с внешним API

Сайт из ЛР1 подключён к моковому REST API на `json-server` с авторизацией через `json-server-auth`. Все данные (рецепты, кулинары, комментарии, лайки, сохранённые, подписки) теперь хранятся в `db.json` и загружаются через `fetch`.

## Запуск

```bash
npm install
npm start
```

Сервер поднимает API и раздаёт страницы сайта на одном адресе: <http://localhost:3000>.

Демо-аккаунт: `demo@povaryoshka.ru` / `povar2026` (у остальных пользователей в `db.json` тот же пароль).

> json-server сохраняет все изменения прямо в `db.json`. Чтобы вернуть исходные данные, выполните `git checkout db.json`.

## API

| Ресурс | Права (`routes.json`) | Где используется |
| --- | --- | --- |
| `POST /register`, `POST /login` | открыто | регистрация и вход, ответ содержит `accessToken` |
| `/users` | 644: читать могут все, менять — только владелец | страница кулинара, редактирование профиля |
| `/recipes` | 644 | поиск с фильтрами, страница рецепта, мои рецепты |
| `/comments` | 644 | комментарии к рецепту |
| `/likes` | 644 | лайки |
| `/subscriptions` | 644 | подписки на кулинаров |
| `/saves` | 600: только владелец* | сохранённые рецепты |

\* json-server-auth — учебный модуль: у списков он проверяет только, что в коллекции есть хотя бы одна запись текущего пользователя, а параметры запроса не учитывает. Клиент всегда запрашивает `?userId=<свой id>`, а пустой список (ответ 403) считает отсутствием сохранений.

## Структура скриптов

- `js/api.js` — все запросы к API через одну функцию `request()`, которая добавляет токен;
- `js/auth.js` — сессия в `localStorage`, проверка входа;
- `js/ui.js` — общие шаблоны: карточка рецепта, аватар, шапка, уведомления;
- `js/saves.js` — кнопка «Сохранить» на карточках;
- `js/pages/*.js` — скрипт каждой страницы.
