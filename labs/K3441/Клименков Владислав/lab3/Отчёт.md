## Задача

Перевести приложение RecipeHub с MPA на SPA на Vue 3: подключить роутер, реализовать работу с внешним API через Axios, разделить приложение на компоненты и вынести повторяющийся функционал в composables. Сохранить пользовательские сценарии ЛР2 и достижения ДР2–ДР4: доступность, светлую/тёмную темы и SVG-спрайт.

## Ход работы

Создана ветка `lab-3`, обновлены зависимости: Vite 8, Vue 3, Vue Router 4, Pinia 3, Axios, Bootstrap 5.3.8 из npm. Старые HTML-страницы и ES-модули заменены на SPA-структуру: `src/api`, `src/stores`, `src/composables`, `src/router`, `src/components`, `src/views`.

Реализованы: API-слой на Axios с interceptors, JWT и обработкой ошибок; Pinia-хранилища `auth` и `catalog`; composables `useTheme`, `useLiveRegion`, `useRecipeSearch`, `useBootstrapModal`; роутер с 7 маршрутами, 404-страницей, редиректами со старых URL, guards и meta. Компоненты и views разделены по ответственности. Сохранены доступность (skip-link, ARIA, live-region, фокус на `<main>` после перехода), темы (`system`/`light`/`dark`, `localStorage`, `data-bs-theme`) и SVG-спрайт (17 символов, все используются). Сервер оставлен только как API, добавлено автосоздание `db.json` из `db.seed.json`.

## Вывод

Приложение переведено на Vue 3 SPA с клиентским роутингом, Axios-слоем, Pinia-хранилищами и composable-функциями. Пользовательская функциональность ЛР2 и достижения ДР2–ДР4 сохранены. Ключевой результат — разделение ответственности: API-слой отвечает за HTTP, stores — за данные и социальные связи, composables — за повторяемое поведение, components — за отображение, views — за композицию экрана.

## Дополнение: Подробнее про токен доступа

Токен формирует не Vue-приложение и не сам `json-server`, а middleware `json-server-auth`, работающий внутри Node-сервера и подключённый в `package.json` (`"json-server-auth": "2.1.0"`). Непосредственно JWT подписывает библиотека `jsonwebtoken`, которую `json-server-auth` использует внутри.

Токен создаётся в двух случаях:

- `POST /login` — при успешной проверке e-mail и пароля;
- `POST /register` — сразу после создания нового пользователя.

В обоих случаях выполняется примерно такой вызов:

```js
jwt.sign(
  { email },
  JWT_SECRET_KEY,
  { expiresIn: '1h', subject: String(user.id) },
);
```

Фронтенд же в свою очередь только:

1. получает `accessToken` из ответа API;
2. сохраняет его в `localStorage` или `sessionStorage`;
3. подставляет его в заголовок `Authorization: Bearer <token>`;
4. читает payload токена, чтобы узнать `sub` (id пользователя) и проверить `exp` (срок действия).

Подключение `json-server-auth` происходит в `server/index.js`:

```js
const auth = require('json-server-auth');

const app = jsonServer.create();
const router = jsonServer.router(DB_FILE);

// json-server-auth проверяет владение ресурсом по полю userId,
// поэтому ему нужен доступ к базе.
app.db = router.db;

app.use(middlewares);

app.use(
  auth.rewriter({
    users: 644,
    recipes: 644,
    comments: 644,
    likes: 644,
    bookmarks: 644,
    subscriptions: 644,
  }),
);

app.use(auth);
app.use(router);
```

Сам токен имеет такой header:

```json
{
  "alg": "HS256",
  "typ": "JWT"
}
```

И такой payload:

```json
{
  "email": "demo@recipehub.ru",
  "iat": 1794653955,
  "exp": 1794657555,
  "sub": "1"
}
```

| Claim | Значение |
|---|---|
| `sub` | id пользователя в виде строки |
| `email` | e-mail пользователя |
| `iat` | время выдачи токена (UNIX-время) |
| `exp` | время истечения (UNIX-время) |

`exp - iat = 3600` секунд, то есть токен живёт 1 час.
