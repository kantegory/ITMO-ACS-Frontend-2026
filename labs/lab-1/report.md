# Отчёт — лабораторная работа №1 (TableBook)

## Задача

Сверстать многостраничный сайт бронирования столиков в ресторанах без использования
фреймворков и без обращения к серверу — вся логика должна работать на статичном HTML, CSS
и JavaScript, а данные храниться прямо в коде.

## Ход работы

Сайт разбит на пять страниц: главная с поиском и фильтрами ресторанов, страница конкретного
ресторана с меню, фото и отзывами, страницы входа и регистрации, личный кабинет пользователя
с историей бронирований.

Данные о ресторанах вынесены в `js/data.js` в виде массива объектов (название, кухня, город,
цена, рейтинг, фотографии, меню, отзывы). Backend отсутствует, поэтому авторизация и
бронирования эмулируются через `localStorage`: `js/auth.js` сохраняет туда текущего
пользователя, `js/profile.js` — список бронирований.

Разбивка по файлам:

- `index.html`, `js/search.js` — поиск и фильтрация ресторанов по кухне, городу и цене;
- `restaurant.html`, `js/restaurant.js` — страница ресторана, вкладки с меню/фото/отзывами,
  модальное окно бронирования;
- `login.html`, `register.html`, `js/auth.js` — вход и регистрация с проверкой полей на
  стороне клиента;
- `profile.html`, `js/profile.js` — личный кабинет, список бронирований и возможность их
  отменить;
- `js/common.js` — общие функции для всех страниц: навигация, рендер карточек;
- `css/style.css` — стили, вёрстка на Bootstrap с собственными доработками.

В результате получился полностью рабочий сайт: пользователь может искать рестораны,
смотреть карточку ресторана, регистрироваться/входить и бронировать столик — всё это работает
только в рамках одного браузера, без обмена данными с внешним хранилищем.

## Вывод

Получен рабочий прототип сайта, где вся бизнес-логика выполняется на клиенте. Такой подход
подходит только для демонстрации интерфейса — реальных данных между пользователями или
устройствами он не синхронизирует, что и стало отправной точкой для следующей лабораторной
работы, где появляется сервер.
