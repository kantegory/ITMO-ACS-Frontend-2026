# Отчёт — лабораторная работа №3 (миграция на Vue.js)

## Задача

Мигрировать приложение бронирования столиков (результаты лабораторных работ №1 и №2) с
статичного HTML/JS на Vue 3 + Vite, сохранив прежнюю бизнес-логику и REST API.

## Ход работы

Проект пересобран как SPA на стеке Vue 3 (`<script setup>`), Vue Router 4 и Axios.

- `src/views` — страницы, на которые ведёт роутер (главная, вход, регистрация, профиль,
  страница ресторана) — раньше это были отдельные HTML-файлы;
- `src/components` — переиспользуемые компоненты (навбар, карточка ресторана, фильтры,
  модалка бронирования, звёздный рейтинг, пункт истории бронирований), выделенные из
  прежнего разрозненного кода в `js/search.js`, `js/restaurant.js`, `js/profile.js`;
- `src/api` — axios-клиент и обёртки над REST-эндпоинтами мокового API (аналог прежнего
  `js/api.js` из лабораторной №2, перенесённый без изменения контракта запросов);
- `src/composables` — общая логика, не привязанная к конкретному компоненту: `useAuth`
  (авторизация и сессия), `useAsync` (загрузка данных с состояниями pending/error),
  `useRestaurantDisplay` (форматирование данных ресторана для отображения).

Backend не менялся — используется тот же `json-server-auth` на `http://localhost:3001`
(`npm run server`), а сам Vue-проект запускается через Vite dev server (`npm run dev`) на
`http://localhost:5173`.

## Вывод

Переход на Vue заменил ручное управление DOM и обработчиками событий на декларативный,
компонентный подход: вёрстка и логика страниц теперь разбиты на самостоятельные Vue-компоненты,
а повторяющаяся логика (авторизация, загрузка данных, отображение ресторана) вынесена в
composables. Слой работы с API при этом остался прежним — подтвердилось, что архитектура
обращений к серверу, выстроенная в лабораторной работе №2, не зависела от конкретного способа
отображения данных.
