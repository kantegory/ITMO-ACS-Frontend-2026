# Лабораторная работа 2. Работа с API

**Исполнитель** — Даниил Кутуков, К3439.

## Запуск

Из этой директории выполните `npm ci`, затем `npm start`. Откройте [Столик](http://localhost:3000/). Сервер одновременно предоставляет интерфейс из ЛР1 и API. При первом запуске создаётся `db.json` с учебным каталогом. Аккаунты и бронирования сохраняются в этой базе, сессии действуют до выхода, перезапуска сервера или истечения 12 часов. Для демонстрации используйте вымышленные почту и пароль.

## Проверка

- `GET /api/restaurants` принимает `query`, `cuisine`, `district` и `price`. `GET /api/restaurants/:id` возвращает карточку выбранного ресторана.
- `POST /api/register` и `POST /api/login` возвращают профиль и токен. Клиент сохраняет сессию в `sessionStorage`.
- `GET /api/bookings`, `POST /api/bookings` и `PATCH /api/bookings/:id` требуют заголовок `Authorization: Bearer …`. У каждого аккаунта своя история. Проверьте через инструменты разработчика, что фильтрация и изменение истории отправляют запросы через `fetch`.
- ДЗ2, ДЗ3 и ДЗ4 можно открыть по путям [ДЗ2](http://localhost:3000/hw2/), [ДЗ3](http://localhost:3000/hw3/) и [ДЗ4](http://localhost:3000/hw4/), если их файлы присутствуют в рабочей копии.

JSON Server хранит данные и обрабатывает запрос карточки ресторана. Middleware проверяет токены, права на бронирования и данные формы.
